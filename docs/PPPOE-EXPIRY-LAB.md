# LAB-HEX PPPoE expiry controls

Scope: LAB-HEX E50UG only. This is a lab repair, not a production deployment template. It does not modify the NetOps global expiry policy. CCR, production HEX and RBX remain excluded.

## Problem

RADIUS correctly returned a 512k/512k rate and Mikrotik-Address-List=no-internet for an expired PPPoE account, but LAB-HEX had no firewall rules consuming that list. The list/rate alone did not implement renewal-only access. The generic Expired page instructions also enabled a proxy without explicit proxy-client restrictions; those instructions were not pasted verbatim.

## Prerequisites and backup

This script was prepared after inspecting this router's firewall and proxy. Its original proxy was disabled, port 8080, no access rules, 600 client/server connections, no disk cache, unlimited cache size. Default firewall anchors and PPP pool are specific to this lab. Check the current configuration and refuse to overwrite an unrelated proxy or ruleset.

Private rollback exports were saved on the router before mutation:

- lab-before-pppoe-expiry.rsc (firewall export)
- lab-before-pppoe-proxy.rsc (proxy export)

Do not publish router exports or enrolment scripts. A whole-firewall re-import is not the preferred rollback: it can duplicate unrelated rules.

## What was added

`scripts/lab/pppoe-expiry.rsc` adds only rules identified by netops-expiry comments, and skips them on a repeated import. Import the complete file so the LAB-HEX identity guard aborts execution on any other device. Do not paste subsequent lines after an identity-guard error.

- IPv4 source scope: 10.20.0.0/22 AND membership in no-internet.
- Forward jump placed before default IPsec/established accepts. Only portal-IP TCP 80/443 is allowed; other forwarding drops.
- Restricted input chain permits DNS TCP/UDP 53 and renewal redirect TCP 8099, then drops other router access.
- A separate input drop on TCP 8099 precedes established/default LAN acceptance, blocking every other proxy client (including WAN/management/hotspot clients).
- Proxy ACL redirects PPP subnet requests to a fixed HTTPS renewal URL; a deny-all ACL follows. No arbitrary upstream proxying is permitted. Cache is disabled and connection counts bounded.
- NAT redirects restricted DNS to the router and plain HTTP to the renewal redirect. HTTPS is not intercepted or decrypted.
- Portal address list uses a DNS entry so resolved addresses can update.

### Limits

The portal hostname resolves to shared Cloudflare IPs. Firewall IP allowances cannot enforce hostname/SNI isolation on those shared addresses. Treat this as limited portal-address access, not cryptographic domain-only filtering. Payment integrations may need additional explicitly reviewed destinations; no M-Pesa transaction was tested through this ruleset. If strict hostname isolation is required, use a dedicated portal endpoint/IP or a separate reviewed gateway design.

The observed router had only IPv6 loopback/link-local addresses and no IPv6 pool. This ruleset does not implement an IPv6 captive gateway; do not enable global IPv6/PD on PPPoE without matching expiry controls.

## Validation

Use real Cambium/customer traffic for end-to-end proof; a fetch generated by the MikroTik itself does not traverse the customer forwarding path.

1. With an active entitlement, confirm RADIUS PPPoE login, expected queue, no no-internet address-list entry, and customer browsing.
2. Set only the lab user's entitlement to a short future expiry, reconnect once to receive Session-Timeout, and wait without manually disconnecting at the deadline.
3. Confirm timeout in router logs, automatic redial, dynamic no-internet entry, 512k queue, and increasing expired-forward drop counters under client traffic.
4. From a laptop behind Cambium, open plain HTTP and verify redirect to the fixed HTTPS renewal page; confirm portal access, normal HTTPS-site failure and working DNS. Verify NAT/proxy counters. Do not use a hotspot/management laptop as a substitute path.
5. Test a non-expired client cannot use port 8099 as an open proxy.
6. Restore the original entitlement and reconnect. Confirm no-internet entry disappears, original queue returns and internet recovers.
7. Re-import to verify idempotency (counts unchanged); check existing hotspot and admin connectivity afterward.

Only mark steps passed when actually observed; keep configuration checks distinct from customer-side browsing tests.

## Rollback

For the original settings recorded above only, import `scripts/lab/pppoe-expiry-rollback.rsc`. It disables the new proxy and removes only owned comments/address-list entries. It preserves unrelated firewall/hotspot rules. Do not use this rollback if another operator has since repurposed the proxy. Do not reboot, reset or upgrade the router.

## Live results — November 10, 2026

Natural expiry at 00:51:00 terminated user1 with `connect time expired`; Cambium redialled at 00:51:12. The restricted session received 512k/512k and a dynamic no-internet entry. Customer traffic hit the forward drop (6 packets / 887 bytes) and redirected DNS (6 packets / 378 bytes). A non-expired local proxy attempt hit the separate deny rule (2 packets / 120 bytes). Reapplying the guarded commands left counts unchanged: 9 filters, 3 NAT rules, 2 proxy ACLs.

The HTTP redirect had zero observed hits, so customer-side renewal-page navigation remains unverified. The original 01:08 entitlement was restored and the session reauthenticated. No payment, SMS, credential or production-router change was made.
