# Five fixes (2026-11-15): deploy, verify, and the two-device test

Branch `claude/netops-five-fixes`, based on `4044d52`. Nothing here is live until it is merged into
`claude/always-online-hosting`, the branch auto-deploy pulls. No database migration is needed. Existing sessions, payments,
balances, passwords and accounting records are not changed.

## What changed

| # | Problem | Root cause | Fix |
|---|---|---|---|
| 1 | Old sessions shown as "Online" in a customer's history | The history column printed "Online" for any session with no Stop. The customer page's Active Sessions card used its own 20-minute window, and the accounting log used 30 minutes. | One rule in `lib/online.cjs`: active = no Stop and updated within 15 minutes (the RADIUS policy), and not replaced by a newer session from the same device. Labels are Online, a stop time, "Ended · no Stop received" or "Ended · reconnected (no Stop received)". The history, the Active Sessions card and the accounting log all use it. No stop times are invented and nothing is deleted. |
| 2 | Online now said 77 while the breakdown said 1 Hotspot + 29 PPPoE | 77 was the routers' active-table row counts (sessions, including accounts NetOps doesn't know, with no freshness check). The breakdown counted only NetOps accounts that are paid and online, and hotspot only for accounts seen today. | One count: connections (one per device login) from router reports under 15 minutes old plus active RADIUS sessions, merged by router, service, username and MAC. The breakdown by service, by account status (paid / expired / deactivated / not in NetOps) and by router each add up to the total. Routers with stale reports are named and not counted. The measurement time is shown. The router cards and the live view use the same numbers. |
| 3 | Hotspot servers showed 0 on LAB-HEX with 1 user active | `servers()` counted only router discovery reports under 5 minutes old and never looked at RADIUS. A RADIUS-only user, or a report 5–15 minutes old, gave 0. | Counts come from the same merged connections. A connection goes to a server only when the router row names it, RADIUS sends it (`Called-Station-Id`, now stored for hotspot sessions), or the router has exactly one hotspot server. Anything else gets a "Server not reported" row. With no fresh evidence the count shows **Unknown**, not 0. |
| 4 | Router jobs showed the hotspot password for "Connect hotspot device" | Job lists and create/retry/connect responses returned stored job objects whole. | `jobs.redact()` masks secret-named fields at any depth, and their values inside output/error text, for every staff-facing response: the job list, create, retry/cancel, customer Connect, customer job history and system logs. Router error text is scrubbed before it is stored. The UI also masks these fields. The router's job runner still gets the password, on retries too. |
| 5 | Extend saved, but the open profile stayed old until reload | The Extend callback (and about 15 other profile actions) showed a toast and never reloaded the profile. | After success, the profile reloads for the same customer only. Failures stay in the form with no success message. Double submit is blocked. A late answer never pulls the page back to a customer you have left. Renew, Record payment and Edit refresh too. |

## Before deploying: backup (on the server)

This takes a consistent copy of the live database while the hub keeps running, so there is no downtime for RADIUS logins.
`master.key` is copied next to it; the database is useless without it.

```bash
cd ~/network-hub
docker compose exec hub node -e "
const {DatabaseSync}=require('node:sqlite'),fs=require('node:fs'),d=process.env.NETWORK_DATA_DIR||'/data',t=new Date().toISOString().replace(/[:.]/g,'-');
fs.mkdirSync(d+'/backups',{recursive:true});const db=new DatabaseSync(d+'/network.sqlite');db.exec(\"VACUUM INTO '\"+d+'/backups/pre-fixes-'+t+\".sqlite'\");db.close();
fs.copyFileSync(d+'/master.key',d+'/backups/pre-fixes-'+t+'.master.key');
const b=new DatabaseSync(d+'/backups/pre-fixes-'+t+'.sqlite',{readOnly:true});console.log('backup',t,'records',b.prepare('SELECT count(*) n FROM records').get().n,'integrity',b.prepare('PRAGMA integrity_check').get().integrity_check);"
```

Expect `integrity ok`. Copy the two files out of the volume as well if you want an off-server copy:
`docker compose cp hub:/data/backups ./backups-pre-fixes`.

Record the commit that is live now, for rollback:

```bash
git -C ~/network-hub log -1 --format='%h %s'
```

## Deploy (only after the owner says so)

Merge the branch into the auto-deploy branch. Cron rebuilds the hub within about 2 minutes.

```bash
git fetch origin && git checkout claude/always-online-hosting && git pull --no-rebase
git merge --no-ff origin/claude/netops-five-fixes && npm test && git push origin claude/always-online-hosting
```

**Undo:** `git revert -m 1 <merge commit>` and push. Only code changes; the backup above is for safety.

## Two-device test (LAB-HEX only, physical devices needed)

Account `lab-two-device-qa`, package Lab Day (5/5 Mbps, 2 devices). First check its current state read-only, in NetOps and
on LAB-HEX:

- NetOps → customer `lab-two-device-qa`: status, expiry, Active Sessions (should be 0 before starting).
- NetOps → Hotspot → Vouchers: is `CS662FAR` unused, used, or used by which account? Use it only if it is unused or already
  belongs to this account. Otherwise extend the account with **Extend** (a manual change, no payment). Do not buy, do not use M-Pesa.
- LAB-HEX terminal: `/ip hotspot active print where user="lab-two-device-qa"` (read-only).

Then:

1. Device A, then device B: sign in with the shared-account flow (the account's username and password on the login page, or
   the voucher). On each, open a page that is not in the walled garden (e.g. `http://neverssl.com`) and run a speed test. Expect about 5 Mbps.
2. Device C: sign in. **Expected: refused.** The refusal comes from RADIUS, not the portal: Hotspot → Auth logs shows
   Access-Reject "Device limit reached" for the account, and the router login page shows the router's error. If the auth log
   shows nothing, the refusal came from the portal or the router before RADIUS. Note the exact message.
3. A and B still browse. Hotspot active users and the customer's Active Sessions show exactly 2, the dashboard counts 2
   connections and 1 customer for this account, and the hotspot server row on LAB-HEX counts 2.
4. Release a slot: on device A open the logout page (`wifi.kadenetworks.com/logout`, or the router's status page → Log out).
   The router sends a Stop, so the slot frees at once. Check that Active Sessions drops to 1.
5. Device C signs in again. **Expected: accepted**, and browsing works.

**Known limit (not changed):** RADIUS counts a slot as used for up to 15 minutes when a device drops off without a Stop
(Wi-Fi out of range, router restart). If step 5 is refused right after a device simply walked away, rather than logging out,
that is why. Wait 15 minutes or use Log out. The limit was not weakened.

## Later the same day: the Disconnect page on wifi.kadenetworks.com/status

The router shows its own `logout.html` after Disconnect. The netops version of that page was added on 2026-11-12, but it
only reaches a router through a page push, and LAB-HEX never had one after that, so it still shows MikroTik's built-in page.
The netops page itself renders correctly.

Router jobs now shows **WiFi pages out of date** for a router whose last successful page push is older than the current
login/status/Disconnect pages (or status design), with an **Update WiFi pages** button. The button queues the existing
"Put the netops WiFi pages on this router" job. That job only rewrites login.html, status.html and logout.html in each
hotspot folder and adds the portal address to the walled garden if it is missing. The button is offered only on routers that
already run netops pages, so never on the ISPman production routers. Nothing is queued automatically.

**For LAB-HEX:** NetOps → MikroTik → Router jobs → LAB-HEX → Update WiFi pages. Then connect a phone, open
`wifi.kadenetworks.com/status` and press Disconnect.
