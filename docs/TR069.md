# Independent TR-069 service

Installed on 2026-10-20. The owner dashboard is connected to the private GenieACS NBI. The public device endpoint is **https://netops.kadenetworks.com/cwmp/**.

## Current hardware status

RBX (RB951Ui-2HnD, RouterOS 7.24) has its existing TR-069 package enabled, fresh per-device credentials and a one-minute periodic Inform. Authenticated physical bootstrap, subsequent periodic Inform sessions and a read-only parameter refresh are verified. The refresh returned model/software, uptime and two actual Wi-Fi SSIDs. No previous ACS URL was replaced. The temporary installers removed themselves. Router monitoring for HEX, CCR and RBX is a separate outbound HTTPS service. No separate ONT/CPE was found in the deployed app's inventory or open management pages.

RouterOS 7.24 supports built-in CA trust by service. The original `default` selection was expanded using the router's own `current-defaults` value, then TR-069 was added. Do not combine the literal `default` enum with a service: RouterOS rejects that combination. For a device still using the default group, the correctly guarded command is:

```routeros
{
 :if ([:tostr [/certificate settings get builtin-trust-store]] != "default") do={ :error "Review the existing custom trust services first"; }
 :local services [/certificate settings get current-defaults];
 /certificate settings set builtin-trust-store=($services,"tr069");
}
```

On this firmware the built-in service change alone did not resolve TR-069's CA error. [MikroTik's TR-069 documentation](https://help.mikrotik.com/docs/spaces/ROS/pages/9863195/TR-069?sortBy=name&sortOrder=ascending) requires importing the root CA for HTTPS. The deployed public endpoint's verified chain uses Google Trust Services WE1 / GTS Root R4. The root was downloaded from `https://pki.goog/repo/certs/gtsr4.pem` with certificate checking enabled, imported initially untrusted, and marked trusted for **TR-069 only** after its SHA-256 fingerprint matched:

```text
34:9D:FA:40:58:C5:E2:63:12:3B:39:8A:E7:95:57:3C:4E:13:13:C8:3F:E6:8F:93:55:6C:D5:E8:03:1B:3C:7D
```

The source, fingerprint, CA property and self-signature were independently verified against [Google's CA repository](https://pki.goog/repository/). The imported certificate is named `network-hub-gts-root-r4`. The temporary download was removed; certificate verification remains enabled. Future devices need the actual endpoint chain checked again, since Cloudflare can change its issuer. Do not trust a supplied certificate solely because its name matches, set the trust store to `all`, disable verification or overwrite another provider's ACS.

The dashboard's TR-069 page displays the actual serial, model, software and check-in time. Use **Refresh parameters** first; verify the next device session and updated parameter timestamps. Queue acceptance is not proof of execution. Inbound connection requests may be unreachable behind NAT, so queued operations can wait for the next periodic Inform. Reboot and Wi-Fi changes need separate, intentional device tests. An ONT/CPE test still needs the actual model and a signed-in management session.

Windows and WSL were initially observed about one hour apart, and the competing Linux time service caused a clock jump during the first refresh. This invalidated the session. Linux time synchronization was disabled in the dedicated distribution, WSL was aligned with Windows and the dedicated ACS services were restarted. The original queued refresh then completed, its fault cleared and real parameter values appeared. The local journal was marked **Reconciled by operator** after those observations were checked; an HTTP queue receipt was not relabeled as an execution receipt.

Device freshness and check-in age use the ACS NBI response's valid HTTP Date; if missing or invalid, local time is used. The UI discloses differences over one minute and retains the original check-in timestamp. A stale device remains offline relative to the ACS clock; the app does not replace old timestamps with local arrival time. Windows time settings were not changed. The startup launcher now aligns WSL with Windows when they differ by more than five seconds and restarts CWMP/NBI after a correction to discard old session timers. Accurate Windows host time remains a deployment requirement.

## Installed layout

| Component | Location / listener |
| --- | --- |
| WSL distribution | NetworkHub-ACS; Ubuntu 24.04.5 LTS |
| Runtime | /opt/network-hub-acs; Node 24.21.0, GenieACS 1.2.16 |
| MongoDB | 8.0.34; authenticated, 127.0.0.1:27017 |
| GenieACS CWMP | 127.0.0.1:7547; private backend for the isolation proxy |
| CWMP connection isolation | 127.0.0.1:7548; the tunnel origin for /cwmp/, forwards to 7547 |
| NBI | 127.0.0.1:7557; only the local dashboard uses it |
| Secrets | /etc/network-hub-acs; root-owned, no public route |
| Logs | /var/log/network-hub-acs; seven daily rotations |
| Windows keeper | Kade Network Hub ACS scheduled task at sign-in |

Unknown serials are rejected. `/etc/network-hub-acs/cpes.json` contains enabled serials and independent random device passwords. The CWMP authentication expression checks enrollment and authenticates the serial as the username. MongoDB has a separate application user restricted to its GenieACS database. The optional GenieACS UI and file server are not started. NBI must never be exposed without authentication.

`network-hub-acs-proxy.service` runs the small Node HTTP proxy in `deployment/acs/cwmp-proxy.cjs`. A tunnel may reuse its origin sockets for different clients, while GenieACS associates active sessions with sockets. The proxy forwards cookies, authentication and SOAP data using a fresh connection to GenieACS per request, so sessions cannot be mixed by that pooling. It accepts only POST, limits requests to 8 MiB, applies timeouts and logs neither credentials nor message bodies. CWMP remains protected by device authentication and public HTTPS. A protocol fixture tests interleaved CPE sessions, cookie/body forwarding, request limits and an unavailable upstream.

**Refresh parameters** now requests the identity, software, uptime, SSID, enable state and access-point references needed by this dashboard through `getParameterValues`, with GenieACS wildcard discovery for supported Wi-Fi instances. It does not scan the entire device root. RBX exposes optional diagnostics with missing values; a full-root refresh can exhaust GenieACS commit iterations. The old read-only root task was archived and retired before validating the bounded request. Existing Wi-Fi passwords and unrelated diagnostic trees are excluded from the new refresh.

## Reproduce on a new host

These commands are installation steps for a new dedicated environment, not a reason to reinstall the running host. Run from the project folder. Replace the distribution location for another PC.

```powershell
wsl --install Ubuntu-24.04 --name NetworkHub-ACS --location C:\Users\hp\Documents\codex1\.tools\wsl\network-hub-acs --no-launch --web-download
wsl --distribution NetworkHub-ACS --user root --exec bash /mnt/c/Users/hp/Documents/codex1/network-dashboard/deployment/acs/install-ubuntu.sh
.\scripts\install-acs-startup.ps1 -StartNow
.\scripts\configure-acs-ingress.ps1 -CloudflaredPath C:\Users\hp\Documents\codex1\.tools\cloudflared\cloudflared.exe
```

The Linux installer targets Ubuntu 24.04, uses MongoDB's signed official repository and checks the official Node archive SHA-256. GenieACS's bundled dependencies receive compatible pinned security updates and must pass an npm runtime audit. Re-running the installer retains existing secrets and restarts the dedicated ACS services. Review service interruptions before running it against active equipment.

The ingress helper validates the proposed configuration and preserves a private backup before adding the CWMP route. Restart the existing project tunnel to load it. This does not create a new DNS record or change the Cloudflare plan. A browser-based Cloudflare Access challenge is unsuitable for CPEs.

In **TR-069 → Connect ACS**, use NBI `http://127.0.0.1:7557`, leave NBI proxy credentials empty for this local connection, and set the public ACS URL above. CPE credentials are different from NBI credentials.

## Enroll another device

Inspect the actual model, firmware, TR-069 package, serial, existing ACS and supported data model first. Do not replace an active provider's ACS automatically. This helper generates RouterOS syntax; it is not an all-vendor ONT installer.

Run the helper inside Linux as root, passing the confirmed serial, a label, the public ACS URL and a private output file. The example uses a placeholder serial and must be replaced before use:

```powershell
wsl --distribution NetworkHub-ACS --user root --exec /opt/network-hub-acs/node/bin/node /mnt/c/Users/hp/Documents/codex1/network-dashboard/deployment/acs/enroll-cpe.cjs CONFIRMED_SERIAL ROUTER_LABEL https://netops.kadenetworks.com/cwmp/ /mnt/c/Users/hp/Documents/codex1/network-dashboard/data/acs/private-enrollment.rsc
```

The output contains credentials: keep it private, install it only on the matching router as `network-hub-tr069-setup`, then remove the temporary local file. Repeated generation reuses the enrolled credentials. The script rejects a different hardware serial or a different existing ACS URL and removes only its own temporary setup entry. It leaves certificate trust, LAN, WAN, firewall, RADIUS and other provider scripts unchanged. Disable an enrollment in the private serial registry to deny future sessions; credential rotation and an operator enrollment UI are not implemented.

## Operation and recovery

```powershell
wsl --distribution NetworkHub-ACS --user root --exec systemctl is-active mongod network-hub-acs-cwmp network-hub-acs-nbi network-hub-acs-proxy
Get-ScheduledTask -TaskName 'Kade Network Hub ACS'
```

The Windows task runs `scripts/start-acs-host.ps1`, which holds a file lock, verifies the dedicated host marker, disables its competing Linux NTP service and aligns its clock before keeping WSL alive through `keep-host.sh`. The updated launcher was run through its scheduled task and reported zero clock offset, one keeper process and four active services. systemd restarts a crashed ACS process; the keeper also restarts inactive services. For maintenance, stop the **Kade Network Hub ACS** task and its dedicated `keep-host.sh` process before stopping Linux services, otherwise recovery will restart them. Resume using `scripts/install-acs-startup.ps1 -StartNow`. Stopping the dashboard supervisor alone does not stop ACS.

The PC must stay powered on, awake, online and signed in. No reboot/sign-out test or before-sign-in service has been installed. Retain the Windows private app data, Cloudflare credentials and an independent backup of the WSL virtual disk/database and `/etc/network-hub-acs` secrets. For a consistent WSL export, stop the ACS keeper, shut down only this distribution, export it privately, then resume; do not copy a running virtual disk. Never distribute those backups, device scripts, logs or credentials with source code.
